# 本地 MIDI 与挥拍变速（Stage D）

## 当前结果

本地《欢乐颂》已可播放、循环、手动变速、调整音量、暂停/继续及停止回开头。可切换“手动速度”与“跟随挥拍”。固件沿用已验证的 gx 负向版本，无需再次上传；Python 环境不变，不作为音频运行依赖。

34 项 Node 测试及 Vite 生产构建通过。用户初次试听确认变速正常，但发现暂停/继续回到开头；已修复恢复位置。用户在真实 Chrome 中运行自动音频渲染页，4 项检查全部通过，随后确认主页面可从暂停位置继续。本轮实机挥拍能改变音乐速度，但用户反馈变化不特别明显，记录原因见下文。

## 操作

1. 打开本地网页，等待乐谱加载。“播放音乐”首次点击会启用浏览器声音；不自动播放，无需先连接 Arduino。
2. 默认“手动速度”，范围 50–180 BPM。可先试听 80→120→160 BPM；改变节奏会保持音高与音乐位置。初始速度 100 BPM、音量 -18 dB，可用滑块调整音量。
3. “暂停”立即静音并保留音乐位置；“继续播放”恢复。若在长音中暂停，恢复时会重新发音，剩余时值仍按音乐 tick 结束。“停止并回到开头”清零位置。
4. 右手按已验证方向佩戴，连接 COM3、静止校准、开始检测。将音乐速度来源切换为“跟随挥拍”，点击播放。获得正常拍间隔后，音乐 BPM 跟随测量值，每次更新用约 0.2 秒过渡。
5. 音乐速度与“当前节奏”的设备测量是不同读数。切回“手动速度”恢复滑块保存的速度。停挥、关闭检测、重校准或断开设备时，音乐保持最后速度继续播放；暂停可用播放按钮。后续已接入左手摄像头手势，操作与待测范围见 [左手控制](camera-control.md)。
6. 可导出拍点记录，CSV 同时包含串口回执/BEAT 与 `HOST_MUSIC` 本地操作事件（播放、暂停、停止、速度来源、速度目标、音量）。这些事件可检查接管流程，不是扬声器声音时间戳。

## 实现

本地 `ode.mid` 为 384 PPQ、4/4、16 小节、24,576 ticks，两条声部共 238 个音符，文件初始速度为 100 BPM。没有控制器变化或弯音事件。使用两组 triangle PolySynth，模拟旋律音高与时值；不使用外部音色采样。音色为合成音色。

`midi-score.js` 检查音符数据、跳过打击乐声部，并合并同一声部同音高的真实重叠音符，相邻音符保留重新发音。每个 tick 先释放旧音，再发新音。开始与结束分别按 ticks 排程，因此变速发生在长音途中时，结束位置也随音乐时钟移动。采用文件整体循环，结尾对齐完整小节。

Tone 在循环末尾先回到 loopStart，未必调用 loopEnd tick 的音符结束事件，因此单独监听 loopEnd 释放声部，再播放开头音符。暂停/停止关闭总输出 gate，并销毁声部，防止已经进入 Tone 前瞻队列的音符稍后响起。恢复重新创建声部，并恢复跨越暂停位置的长音。所有自有排程与监听在销毁时清理；开发热更新和离开页面也停止音乐、释放串口。

主音量后有 mute gate 与 -1 dB limiter。后续手势音量可调用现有 `setVolume`；手势暂停/恢复可调用现有播放生命周期，不需要重建另一套播放器。

## 暂停恢复修正

初版保存了正确的小数 tick，但恢复使用 `${tick}i` 字符串。Tone 15.1.22 的 i 表达式仅匹配整数；例如 600.75i 在 100 BPM、480 PPQ 下被解释为 480,600 ticks，跨越循环后回到开头。

当前直接调用暂停时钟的 `transport.start(time)` 保留准确位置；从停止状态开始才显式使用 0i。单元测试后端采用当前 Tone 的实际时间解析器，避免简化模拟器误接受小数 i 字符串。[Tone 时间表示](https://github.com/Tonejs/Tone.js/wiki/Time)

## 验证

- `cd web; npm test`：34 项通过，包括实际本地 MIDI 解析、重叠与相邻音符、note-off 顺序、变速不重启、暂停静音/恢复长音、循环边界、默认预载无声、手动/挥拍来源、停挥/断开保持速度、取消尚未完成的音频启动、加载失败重试和销毁清理。串口 BEAT → 测量 BPM → 音乐目标的集成测试通过，并检查不会重新开始播放。
- `npm run build`：通过，生产 JS 约 306 kB（gzip 约 81 kB）；音乐、模型与 WASM 均来自本地资源。
- Chrome 打开 `/tests/audio-browser.html` 自动检查，不播放声音、不连接设备。使用生产 Tone backend 与 MusicPlayer 渲染实际 Web Audio Buffer；该调试页独立于主界面。
- 用户返回的 4 项实际音频结果保存到 `recordings/audio-offline-20261005.json`：60/120 BPM 的同一音均为约 440 Hz；快速度的结束后 RMS 为 0；长音中从 60 变到 120 BPM 后，结束随音乐 tick 提前，结束后 RMS 为 0；连续三个循环均重新发音；暂停与恢复位置同为 351.0857142857126 ticks。

离线渲染验证音频排程和信号；不代表设备到扬声器的实际响应延迟，也不替代佩戴联动试听。当前工具无法直接控制用户 Chrome，网页观察由用户反馈完成。
