# 左手摄像头控制（Stage E）

> 本文保留 Stage E 实现、测试数据及修正过程；下面的使用方式已对应 dev-4 英文界面。当前完整操作见 [README](../README.md)，最新前端与用户反馈见 [验证记录](testing.md)。

## 当前实现与验证

右手 IMU 控制节奏与挥拍强度；摄像头仅用确认后的生理左手控制音量和暂停/恢复。已实现摄像头操作、镜像预览与关键点显示、左手确认、手动/左手音量来源、手势开关、左手丢失处理及资源清理。固件和 Conda 环境沿用上一阶段。

Stage E 完成时，52 项 Node 测试和 Vite 生产构建通过；当前完整套件为 68 项 Node 检查。此前用户在真实 Chrome 运行视觉诊断页，2 项检查通过：本地模型和 WASM 在 classic Worker 中加载约 379 ms，两个空白图像的识别约 95/22 ms。结果保存到 `recordings/vision-runtime-20261005.json`。诊断页未启用摄像头，也未播放声音；这些结果不代表实际手部识别准确率或帧率。

2026-10-10 用户已确认实际摄像头开启、左手确认/追踪、音量数值与听感、3 轮暂停/恢复、右手单独出现不误控、左手丢失保持以及摄像头重开后的控制恢复。右手隔离/生命周期 CSV 验证 8 对暂停/恢复 tick 一致和丢失期间保持控制值；重开后重新确认按用户反馈记录。随后 IMU/摄像头联动两段实测通过，联动 CSV 中 12 对暂停/恢复 tick 一致，暂停期间仍可接收拍点。双手同框/交叉及音量稳定性定量验证尚未完成。涉及用户的测试必须先汇报目的和动作，然后停下，等待用户明确说“开始测试”后再执行。

## 使用方式

1. 初始窗口或 Devices 中选择 Conduct，完成右手 Connect / Calibrate，进入 Left hand 步骤后点击 Enable，并在 Chrome 中允许摄像头访问。窗口关闭不会结束摄像头会话。
2. 只举起左手，右手暂时离开画面。模型连续稳定识别一只手至少 700 ms 后，Confirm 可用；用户确认当前举的是生理左手后点击。
3. Conduct 默认以 Left-hand height 控制音量，也可在 Settings 切换来源。左手掌中心越高越响，越低越轻。画面高度约 20% 对应 -3 dB，约 80% 对应 -30 dB，超出范围保持边界值。左手位置使用约 220 ms 的时间平滑。
4. 点击 Enter studio，再点击 Play 启用声音与挥拍检测。左手握拳沿用 Lab4 的 0.65 阈值和连续 3 次确认；张掌使用 0.55 阈值和连续 5 次确认。持续同一手势只执行一次，停止状态不会由张掌自动开始播放。Settings 中可关闭 Left-hand pause & resume gestures，单独使用音量控制。
5. 音乐暂停期间保留音量。左手丢失、选择不确定、识别置信度不足时也保留音量，清除未完成的手势计时；丢失超过 500 ms 显示左手丢失，音乐不自动暂停。仅剩右手时同样按左手丢失处理。
6. 切回 Manual slider 音量时恢复此前保存的滑块值。Devices 的 Left hand 步骤可关闭或重新启用摄像头；关闭摄像头、离开页面或开发热更新会停止轨道并终止识别 Worker，重新开启需再次 Confirm 左手。
7. Settings 的 Download CSV 同时保存 `HOST_VISION` 的摄像头、左手确认、追踪状态、音量来源、原始手势读数变化和手势操作事件，以及 `HOST_MUSIC` 的实际音乐操作。视频图像与逐帧关键点不写入 CSV；可通过 Open diagnostics 获取可复制的状态快照。

## 模块与约束

- `vision.js` 管理摄像头启动/取消/停止，传送 ImageBitmap，释放轨道和 Worker。每次只允许一帧在处理，最多约 20 FPS，重复视频帧跳过，超过 250 ms 的过期结果不用于控制。
- `public/mediapipe/vision-worker.js` 使用 CPU 模型推理；classic Worker 可直接运行当前 MediaPipe 1.0.1 的 `importScripts` WASM 加载流程。IIFE、WASM 和模型均来自本仓库本地资源。`npm run dev` 与 `npm run build` 均同步锁定版本运行资源。
- `hand-control.js` 处理确认、左右标签、同索引结果选择、手掌位置平滑、连续手势与丢失。模型检测上限为两只手，只有已确认的左手标签进入控制。左右置信度阈值为 0.7，仅保留 `Open_Palm`/`Closed_Fist`。握拳 0.65 / 连续 3 次，张掌 0.55 / 连续 5 次；重复或倒退时间戳不增加计数，低置信度、丢失和过长帧间隔清除候选。调试区显示原始分类与分数，CSV 的 `GESTURE_READING` 保存类别/接受状态变化及限频的分数变化，并包含实际阈值和所需次数。
- “复制调试信息”在点击时固定快照，尝试写入剪贴板；浏览器拒绝剪贴板时仍可从只读文本框复制。实时刷新不修改该文本框。手势关闭时控制确认进度清零，原始分类与分数仍可查看。
- 左手确认保存实际左手在当前输入管线中的模型标签，不使用画面左半边或结果数组第一项推断生理左手。确认时必须仅举左手；手别模型仍可能误分类，需要实机验证双手同时出现、交叉和右手单独出现。
- 手势调用现有 MusicSession 的暂停/恢复，沿用音乐位置与静音处理；右手 IMU 和音量控制彼此独立。音量更新至少间隔 100 ms、变化至少 0.25 dB，以减少无意义的重复排程与日志。

## 右手隔离、丢失与重开验证

用户实测反馈：仅右手入镜并改变高度、握拳/张掌时，音量保持、音乐继续、左手仍显示丢失；摄像头关闭后音乐与音量保持，重开后必须重新确认左手，确认后高度音量与暂停/恢复正常。

导出 `Final/tmp/air-conductor-beats-2026-10-10-23-11-28.csv` 共 402 条记录：186 条 `HOST_VISION`、216 条 `HOST_MUSIC`。来源为左手高度、音乐速度为手动 100 BPM。包含 8 次手势暂停、8 次手势恢复，8 对音乐暂停/播放 tick 均完全一致。18 段从 `HAND_STATUS,lost` 到恢复追踪或摄像头关闭的区间内，音量更新和播放操作均为 0；最长约 41.478 秒。

摄像头关闭回执为本地 23:09:01.793，重开为 23:09:05.269。文件在重开事件结束，未包含第二次 `BIND_LEFT` 或后续控制，因此重开后恢复按用户报告通过记录。CSV 不记录视频或实际举起的手，不能独立证明右手动作的执行区间；右手隔离依据用户报告，控制值保持另有日志支持。文件没有 Arduino 拍点，不作为 IMU/视觉联动验证。原始导出保留在 `Final/tmp`，同名归档位于仓库 `recordings/browser/`；开发分支保留并上传，最终发布版才移除并忽略。

## IMU 与摄像头联动验证

用户完成两段测试并报告通过：左手自然张掌固定高度时，右手慢/快下挥使拍数与速度变化，音量基本保持且没有误暂停；右手稳定挥拍时，左手改变高度能调音量，握拳暂停、张掌恢复正常，速度仍跟随右手。
