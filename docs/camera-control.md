# 左手摄像头控制（Stage E）

## 当前实现与验证

右手 IMU 控制节奏与挥拍强度；摄像头仅用确认后的生理左手控制音量和暂停/恢复。已实现摄像头操作、镜像预览与关键点显示、左手确认、手动/左手音量来源、手势开关、左手丢失处理及资源清理。固件和 Conda 环境沿用上一阶段。

46 项 Node 测试和 Vite 生产构建通过。用户在真实 Chrome 运行视觉诊断页，2 项检查通过：本地模型和 WASM 在 classic Worker 中加载约 379 ms，两个空白图像的识别约 95/22 ms。结果保存到 `recordings/vision-runtime-20261005.json`。诊断页未启用摄像头，也未播放声音；这些结果不代表实际手部识别准确率或帧率。

实际摄像头、左右手分离、音量听感与手势播放尚未测试。涉及用户的测试必须先汇报目的和动作，然后停下，等待用户明确说“开始测试”后再执行。

## 使用方式

1. 主页面点击“开启摄像头”，在 Chrome 中允许摄像头访问。该操作独立于 Arduino，不需要先连接 COM3。
2. 只举起左手，右手暂时离开画面。模型连续稳定识别一只手至少 700 ms 后，“确认左手”可用；用户确认当前举的是生理左手后点击。
3. 将音量来源改为“左手高度”。左手掌中心越高越响，越低越轻。画面高度约 20% 对应 -3 dB，约 80% 对应 -30 dB，超出范围保持边界值。左手位置使用约 220 ms 的时间平滑。
4. 点击“播放音乐”启用声音。左手握拳连续至少 500 ms 暂停，左手张掌连续至少 500 ms 恢复暂停位置。持续同一手势只执行一次，停止状态不会由张掌自动开始播放。可关闭播放手势，单独测试音量。
5. 音乐暂停期间保留音量。左手丢失、选择不确定、识别置信度不足时也保留音量，清除未完成的手势计时；丢失超过 500 ms 显示左手丢失，音乐不自动暂停。仅剩右手时同样按左手丢失处理。
6. 切回手动音量时恢复此前保存的滑块值。关闭摄像头、离开页面或开发热更新会停止轨道并终止识别 Worker；重新开启需再次确认左手。
7. 导出拍点记录时，同时保存 `HOST_VISION` 的摄像头、左手确认、追踪状态、音量来源和手势操作事件，以及 `HOST_MUSIC` 的实际音乐操作。视频图像与逐帧关键点不写入 CSV。

## 模块与约束

- `vision.js` 管理摄像头启动/取消/停止，传送 ImageBitmap，释放轨道和 Worker。每次只允许一帧在处理，最多约 20 FPS，重复视频帧跳过，超过 250 ms 的过期结果不用于控制。
- `public/mediapipe/vision-worker.js` 使用 CPU 模型推理；classic Worker 可直接运行当前 MediaPipe 1.0.1 的 `importScripts` WASM 加载流程。IIFE、WASM 和模型均来自本仓库本地资源。`npm run dev` 与 `npm run build` 均同步锁定版本运行资源。
- `hand-control.js` 处理确认、左右标签、同索引结果选择、手掌位置平滑、持续手势与丢失。模型检测上限为两只手，只有已确认的左手标签进入控制。左右置信度和手势置信度初始阈值分别为 0.7。
- 左手确认保存实际左手在当前输入管线中的模型标签，不使用画面左半边或结果数组第一项推断生理左手。确认时必须仅举左手；手别模型仍可能误分类，需要实机验证双手同时出现、交叉和右手单独出现。
- 手势调用现有 MusicSession 的暂停/恢复，沿用音乐位置与静音处理；右手 IMU 和音量控制彼此独立。音量更新至少间隔 100 ms、变化至少 0.25 dB，以减少无意义的重复排程与日志。

## 下一轮人工测试内容

待用户在场并明确开始后，先检查摄像头与左手确认，再依次检查左手抬高/降低、握拳/张掌、仅右手出现、左手离开及摄像头关闭/重开。最后在右手挥拍时保持左手静止，确认音乐速度变化不会带动视觉音量或误暂停。测试前再说明具体动作；当前不启动任何动作测试。
